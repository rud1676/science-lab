스펙트럼 |ck|

가로축은 회전 속도 k(바퀴/주기), 세로축은 로그 눈금. 밝은 막대가 지금 쓰고 있는 화살표예요.

무슨 일이 일어나고 있나

1. 돌아가는 화살표 하나 = eiθ

점 (x, y)를 복소수 z = x + iy로 쓰면, 오일러 공식

e^(iθ) = cos θ + i·sin θ

은 원점에서 길이 1, 각도 θ인 화살표입니다. θ를 시간에 따라 늘리면 화살표가 빙글빙글 돌죠. 여기에 복소수 c를 곱하면 길이는 |c|, 시작 각도는 arg(c)만큼 돌아간 화살표가 됩니다.

c_k · e^(2πikt)  →  길이 |c_k|, 한 주기에 k바퀴, 시작 각도 arg(c_k)

2. 화살표를 이어 붙이면 그림이 된다

화살표들을 꼬리에 머리를 잇듯 연결하면, 마지막 화살표 끝이 지나가는 자리가 곡선을 그립니다.

z(t) = Σ c_k · e^(2πikt)   (t: 0 → 1)

푸리에의 주장은 대담합니다: 적당한 c_k만 고르면 어떤 닫힌 곡선이든 이렇게 그릴 수 있다. 화면 속 원들이 바로 이 화살표들이에요(k가 음수면 시계 방향으로 돕니다).

3. c_k는 어떻게 구하나 — 이산 푸리에 변환

그림을 N개의 점 z₀, z₁, …, z_(N−1)으로 찍었다면,

c_k = (1/N) · Σₙ z_n · e^(−2πikn/N)

직관은 이렇습니다. 그림 전체를 반대 방향(−k)으로 돌리면서 평균을 내면, 원래 k 속도로 돌던 성분만 멈춰서 남고 나머지는 빙글빙글 돌다 평균 0으로 상쇄됩니다. 회전하는 카메라로 같은 속도의 물체만 정지시켜 찍는 것과 같아요.

4. 왜 적은 원으로도 비슷해질까

스펙트럼을 보면 대부분의 크기가 작은 |k|에 몰려 있습니다. 매끄러운 그림일수록 더 그렇죠. 그리고 파스발 정리에 따르면 그림의 "에너지"는 계수들의 제곱합과 정확히 같습니다.

(1/N) Σ |z_n|² = Σ |c_k|²

그래서 큰 화살표부터 K개만 써도 에너지의 대부분을 담아낼 수 있습니다. 패널의 "담아낸 에너지"가 이 비율이에요. 하트는 화살표 10개로 이미 99% 이상입니다.

5. 사각형 모서리의 뿔 — 깁스 현상

사각형을 골라 화살표를 줄여 보세요. 모서리 근처에서 선이 살짝 튀어나옵니다. 화살표를 늘리면 튀어나온 부분이 좁아지긴 하지만 높이는 줄지 않습니다. 날카로운 꺾임을 매끄러운 원들로 흉내 내는 데서 오는 근본적인 한계로, 깁스 현상이라고 부릅니다.

공식 → 코드

복소수 곱셈 (x + iy)(cos + i·sin)을 실수부와 허수부로 풀어 쓰면 끝입니다.

// src/math/fourier.ts — c_k = (1/N) Σ z_n · e^(−2πikn/N)
for (let n = 0; n < N; n++) {
  const angle = -2 * Math.PI * k * n / N;
  const c = Math.cos(angle), s = Math.sin(angle);
  re += x[n] * c - y[n] * s;   // 실수부
  im += x[n] * s + y[n] * c;   // 허수부
}
re /= N; im /= N;
amp = Math.hypot(re, im);      // 화살표 길이 |c_k|
phase = Math.atan2(im, re);    // 시작 각도 arg(c_k)

// 그리기 — z(t) = Σ c_k · e^(2πikt)
for (const term of terms) {
  const a = 2 * Math.PI * term.k * t + term.phase;
  x += term.amp * Math.cos(a);
  y += term.amp * Math.sin(a);
}
